# 2. Основные принципы

При использовании нейросетей Оператор руководствуется следующими принципами:

2.1. **Минимизация данных** — в нейросеть передается только тот объем информации, который объективно необходим для выполнения конкретной задачи.

2.2. **Обезличивание** — если задача может быть выполнена без идентификации человека, персональные данные должны быть предварительно обезличены.

2.3. **Законность** — передача персональных данных допускается только при наличии соответствующего правового основания.

2.4. **Конфиденциальность** — сведения, составляющие персональные данные, коммерческую тайну или иную конфиденциальную информацию, не должны становиться доступными неопределенному кругу лиц.

2.5. **Контролируемость** — перед использованием нового сервиса необходимо определить, кто получает данные, где они обрабатываются и как используются.

2.6. **Запрет несанкционированного обучения моделей** — пользовательские данные не должны передаваться сервису для обучения, дообучения или совершенствования модели, если такая передача не была отдельно разрешена Оператором после соответствующей оценки.

2.7. **Проверка результатов** — результат, созданный нейросетью, не считается автоматически достоверным и подлежит проверке человеком перед использованием.

# 3. Что считается персональными данными

Для целей настоящего Регламента персональными данными считаются любые сведения, которые прямо или косвенно относятся к определенному или определяемому физическому лицу.

В частности:

* фамилия;
* имя;
* отчество;
* номер телефона;
* адрес электронной почты;
* адрес проживания;
* данные документа, удостоверяющего личность;
* сведения о месте работы;
* сведения о транспортном средстве, если они позволяют идентифицировать владельца;
* идентификаторы пользователя;
* сведения из CRM;
* содержание переписки;
* записи телефонных разговоров и сведения о звонках, если они позволяют идентифицировать человека;
* IP-адрес в случаях, когда он рассматривается как относящийся к определенному или определяемому лицу;
* идентификаторы cookie и иные онлайн-идентификаторы в случаях, когда они позволяют идентифицировать человека;
* иные сведения, относящиеся к определенному или определяемому физическому лицу.

# 5. Обезличивание

5.1. Если для выполнения задачи необходимо использовать информацию о клиенте, потенциальном клиенте или другом физическом лице, но идентификация этого лица для выполнения задачи не требуется, данные должны быть предварительно обезличены.

5.2. Перед передачей информации в нейросеть необходимо удалить или заменить:

* ФИО;
* номер телефона;
* адрес электронной почты;
* адрес;
* реквизиты документов;
* идентификаторы;
* ссылки на профили;
* сведения, позволяющие непосредственно установить личность;
* иные сведения, позволяющие определить конкретного человека.

5.3. Вместо персональных данных используются нейтральные обозначения:

> «Клиент А»
> «Клиент Б»
> «Потенциальный клиент»
> «Автомобиль А»

5.4. Недостаточно просто удалить ФИО, если совокупность оставшихся сведений позволяет определить человека.

5.5. Передача обезличенных данных допускается только после проверки того, что восстановление личности по имеющейся информации без дополнительной информации действительно невозможно.

# 6. Использование нейросетей для работы с клиентскими обращениями

6.1. Содержание обращения клиента не должно автоматически копироваться в нейросеть целиком.

6.2. Перед использованием обращения необходимо удалить персональные данные, если они не нужны для решения поставленной задачи.

6.3. Допускается передача обезличенного содержания обращения для:

* классификации запроса;
* подготовки проекта ответа;
* анализа потребностей;
* структурирования требований к автомобилю;
* подготовки вопросов для уточнения потребностей;
* подготовки коммерческого предложения на основе обезличенных сведений.

6.4. Если для решения задачи необходимо использование персональных данных, такая обработка допускается только после проверки правового основания и разрешенности конкретного сервиса.

# 7. Использование нейросетей для документов

7.1. Запрещается загружать в ИИ-сервис оригиналы договоров, заявлений, документов клиентов и иные документы, содержащие персональные данные, если конкретный сервис не прошел процедуру согласования.

7.2. Для анализа документов необходимо предварительно:

1. определить цель обработки;
2. определить, нужны ли персональные данные;
3. удалить ненужные персональные данные;
4. обезличить документ, если это возможно;
5. проверить разрешенный статус сервиса;
6. проверить настройки конфиденциальности;
7. проверить возможность использования данных для обучения модели;
8. проверить наличие трансграничной передачи.

# 9. Запрет обучения модели на пользовательских данных

9.1. Перед использованием ИИ-сервиса необходимо проверить, используются ли пользовательские данные для:

* обучения модели;
* дообучения модели;
* тонкой настройки модели;
* улучшения модели;
* оценки модели;
* формирования обучающих наборов;
* иных целей совершенствования искусственного интеллекта.

9.2. Если сервис позволяет отключить использование данных для обучения, соответствующая настройка должна быть отключена до передачи информации.

9.3. Оператор не должен включать функции, позволяющие сервису использовать пользовательские данные для обучения моделей, без отдельного решения.

9.4. Для рабочих задач приоритет отдается тарифам и режимам сервисов, для которых провайдер прямо заявляет, что пользовательские данные не используются для обучения моделей по умолчанию.

9.5. Например, OpenAI указывает, что для ChatGPT Business, ChatGPT Enterprise и API Platform данные бизнеса по умолчанию не используются для обучения моделей. Для персональных аккаунтов ChatGPT необходимо самостоятельно отключать настройку «Improve the model for everyone».

9.6. Использование персонального аккаунта ИИ-сервиса для обработки персональных данных допускается только после проверки соответствующих настроек и условий конкретного сервиса.

# 10. Разрешенные сервисы

## 10.1. Общий принцип

Перечень разрешенных сервисов является закрытым.

Использование ИИ-сервиса, отсутствующего в настоящем разделе, запрещено для обработки персональных данных до завершения процедуры согласования нового сервиса.

## 10.2. ChatGPT Business / ChatGPT Enterprise / API Platform

ChatGPT Business, ChatGPT Enterprise и API Platform могут использоваться для рабочих задач при соблюдении следующих условий:

* используется рабочий аккаунт;
* доступ защищен надежным паролем;
* включена многофакторная аутентификация, если сервис ее поддерживает;
* не включено добровольное предоставление данных для обучения моделей;
* загружаются только данные, необходимые для конкретной задачи;
* персональные данные используются только при наличии правового основания;
* при возможности данные предварительно обезличиваются;
* запрещается использовать публичные ссылки на чаты и материалы, содержащие персональные данные;
* перед использованием конкретного режима проверяются актуальные условия обработки данных.

OpenAI указывает, что для бизнес-продуктов ChatGPT Business, ChatGPT Enterprise и API Platform данные организации по умолчанию не используются для обучения моделей; для некоторых продуктов доступны дополнительные средства управления хранением и обработкой данных.

## 10.3. Персональный ChatGPT

Персональный ChatGPT может использоваться только для:

* общедоступной информации;
* полностью обезличенной информации;
* информации, не являющейся персональными данными;
* задач, при которых отсутствует передача конфиденциальной информации.

До использования персонального ChatGPT для любой информации, относящейся к клиентам, необходимо отдельно проверить настройки обработки данных.

Для персонального аккаунта ChatGPT настройка «Improve the model for everyone» должна быть отключена, если в сервис передаются данные, которые нельзя использовать для обучения. При отключении этой настройки новые разговоры не используются для обучения моделей.

## 10.4. Lovable

**Lovable не относится к разрешенным сервисам для обработки персональных данных.**

Lovable может использоваться Оператором для разработки и сопровождения программных решений только при условии, что в сервис не передаются не обезличенные персональные данные клиентов, потенциальных клиентов или подписчиков.

Это ограничение установлено в настоящем Регламенте независимо от наличия у Lovable отдельных договорных механизмов защиты данных.

Причина ограничения заключается в необходимости контролировать использование данных сервисом. В актуальных условиях Lovable содержатся положения о возможности использования Customer Data для бизнес-целей, включая развитие и обучение моделей, тогда как отдельный DPA предусматривает иной режим для Customer Personal Data. Для исключения правовой неопределенности Оператор не использует Lovable для не обезличенных персональных данных.

# 11. Сервисы, которые не являются ИИ-сервисами, но используются Оператором

11.1. amoCRM, Telegram, MAX, VK и сервисы телефонии не считаются настоящим Регламентом автоматически разрешенными для передачи любых персональных данных только потому, что они используются Оператором.

11.2. Использование каждого такого сервиса осуществляется в пределах его конкретного назначения и после проверки условий обработки персональных данных.

11.3. Запрещается передавать в мессенджеры или социальные сети больше персональных данных, чем необходимо для соответствующей коммуникации.

11.4. Запрещается использовать публичные чаты, публичные каналы или иные общедоступные механизмы для размещения персональных данных клиентов.

11.5. Доступ к CRM должен предоставляться только лицам, которым он необходим для выполнения соответствующих задач.

# 12. Порядок согласования нового ИИ-сервиса

12.1. До начала использования нового ИИ-сервиса необходимо провести его проверку.

12.2. Проверка проводится по следующим вопросам:

1. полное наименование сервиса;
2. разработчик или оператор сервиса;
3. официальный сайт;
4. страна регистрации разработчика;
5. место хранения данных;
6. место обработки данных;
7. категории данных, которые сервис получает;
8. цели обработки;
9. сроки хранения;
10. порядок удаления данных;
11. передача данных субподрядчикам;
12. трансграничная передача;
13. возможность использования данных для обучения;
14. настройки отключения обучения;
15. возможность публичного распространения;
16. настройки доступа;
17. наличие многофакторной аутентификации;
18. условия конфиденциальности;
19. договорные условия обработки данных;
20. возможность заключения соглашения об обработке данных, если оно необходимо;
21. наличие средств удаления и экспорта данных;
22. соответствие сервиса целям деятельности Оператора.

12.3. Новый сервис разрешается только после документированной оценки указанных факторов.

12.4. При наличии существенной неопределенности относительно обработки персональных данных сервис считается **неразрешенным**.

12.5. До завершения проверки новый сервис может использоваться только с общедоступной информацией, не содержащей персональных данных и конфиденциальной информации.

# 13. Трансграничная передача при использовании ИИ

13.1. Использование иностранного ИИ-сервиса может приводить к трансграничной передаче персональных данных.

13.2. До передачи персональных данных иностранному сервису ответственный обязан установить:

* факт передачи данных за пределы Российской Федерации;
* государство или государства назначения;
* получателя данных;
* состав передаваемых данных;
* цели передачи;
* правовое основание;
* необходимость уведомления уполномоченного органа;
